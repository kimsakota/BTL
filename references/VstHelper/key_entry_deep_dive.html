Struct KeyEntry sử dụng thuộc tính [StructLayout(LayoutKind.Explicit, Size = 32)] để điều khiển chính xác vị trí Byte của từng biến. Chuyển đổi giữa 2 Chế độ bên dưới để xem sự biến hình của bộ nhớ:

VÙNG NHỚ 32 BYTES LIÊN TỤC TRÊN RAM (OFFSET 0 ĐẾN 31) CHẾ ĐỘ: INDEX MODE
💡

Kỹ Thuật Union Overlay (Chồng Lấp Bộ Nhớ 16 Bytes):

Từ Offset 16 đến Offset 31 (16 Bytes cuối), biến Comparer (kiểu Buffer) được xếp đè lên đúng vị trí của các biến Offset, RecordLength, State, Type, KeyState, Calculated. Khi ở giai đoạn đọc/ghi ban đầu, 16 Bytes này dùng làm Buffer chứa chuỗi. Khi đã băm Key xong (Index Mode), 16 Bytes này "biến hình" thành vị trí file đĩa!

⚡ Tối Ưu Hóa CPU L1 Cache Line (64 Bytes)

Tại sao lại là đúng 32 Bytes? Bộ vi xử lý (CPU) nạp dữ liệu từ RAM vào bộ nhớ đệm L1 Cache theo từng đường Cache Line rộng 64 Bytes.

CPU L1 CACHE LINE (ĐỘ DÀI: 64 BYTES) 100% NẠP VỪA KHÍT 2 ENTRIES!
KeyEntry #1
32 Bytes (0 -> 31)
KeyEntry #2
32 Bytes (32 -> 63)

👉 Kết quả: Mỗi lần CPU phát lệnh đọc 1 KeyEntry từ RAM, phần cứng CPU tự động kéo luôn KeyEntry thứ 2 kế bên vào L1 Cache. Khi thuật toán Binary Search / QuickSort duyệt phần tử tiếp theo, nó đã có sẵn trong CPU L1 Cache (0.2ns) $\rightarrow$ Triệt tiêu 40-50% Cache Misses!
